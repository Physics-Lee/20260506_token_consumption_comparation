# BPE 算法的终止条件

BPE（Byte Pair Encoding）在**训练**和**推理**两个阶段的终止机制完全不同。

---

## 训练阶段 — 人工设定上限

BPE 训练是一个无限循环的合并过程，需要外部叫停。

### 流程

```
起始: 256 个基础 token（每个字节一个：0x00 ~ 0xFF）
    ↓
循环:
    1. 扫描全部训练语料，统计所有相邻 token 对的频率
    2. 选出频率最高的那一对
    3. 合并这两个 token 为一个新 token，加入词表
    4. 词表现在有 N+1 个 token
    5. 检查: 词表大小达到预设上限了吗？
       是 → 停止训练
       否 → 回到步骤 1
```

### 谁来定上限

**人**。OpenAI 的训练工程师在训练脚本里写死一个数字：

```python
# 伪代码
vocab_size = 50000  # ← 人定的
while len(vocab) < vocab_size and len(vocab) < len(training_corpus):
    best_pair = find_most_frequent_pair()
    merge(best_pair)
```

这就是为什么编码的名字带数字：

| 编码 | 上限 | 合并次数 |
|------|:---:|------|
| r50k_base | 50,000 | 49,744 次 |
| p50k_base | 50,000 | 49,744 次 |
| cl100k_base | 100,000 | 99,744 次 |
| o200k_base | 200,000 | 199,744 次 |

### 为什么上限不同

- 上限越低 → 词表越小 → 加载快、内存省 → 但 token 切得更碎
- 上限越高 → 词表越大 → 常见词组更可能被合并进去 → token 更少（更省钱）

200K 上限意味着工程师判断"值得为这些额外 token 付出内存和加载时间的代价，换来更短的 token 序列"。

### 能不能不限上限

理论上可以一直合并到"没有相邻对出现次数 ≥ 2"，但实际不这么做：
1. 词表会膨胀到百万级，加载太慢
2. 长尾低频组合对编码效率提升微乎其微
3. 超参实验表明 50K~200K 是性价比最优区间

## 推理阶段 — 自然终止

训练好的词表拿去做 tokenization 时，**不需要人介入**，BPE 会自己停。

### 两种终止情况

#### 情况 1：只剩 1 个 token，没得合并

```
输入: "hello"

字节拆分: ["h", "e", "l", "l", "o"]           (5个)
合并 "he" → ["he", "l", "l", "o"]              (4个)
合并 "hel" → ["hel", "l", "o"]                 (3个)
合并 "hell" → ["hell", "o"]                    (2个)
合并 "hello" → ["hello"]                       (1个)
→ 只剩 1 个 token，无法配对 → 自然终止
```

#### 情况 2：没有任何相邻对在合并表里

```
输入: "xyz123"

字节拆分: ["x", "y", "z", "1", "2", "3"]
查合并表:
  "x"+"y" 不在 ⨯
  "y"+"z" 不在 ⨯
  "z"+"1" 不在 ⨯
  "1"+"2" 不在 ⨯
  "2"+"3" 不在 ⨯
→ 没有任何一对能合并 → 自然终止，结果 6 个 token
```

### 合并表是什么

训练阶段每合并一次，就把那对字节对记录下来，存成 `merges` 表：

```
"h" + "e"   → 合并优先级 1（最早合并，优先级最高）
"he" + "l"  → 合并优先级 5
"hell" + "o" → 合并优先级 382
...
```

推理阶段按这个优先级依次尝试合并。优先级越靠前（越早被合并的），越优先。

### 终止的本质

BPE 推理不靠"词表大小"来判断终止，而是**算法逻辑自然穷尽**：

> 当没有任何相邻 token 对在 merges 表中能找到匹配时，合并循环自然退出。

这个逻辑保证了：
- 输入可以是任意长度（一个词或一本书）
- 不需要预设迭代次数
- 时间复杂度 O(输入长度 × 每次合并的查找开销)

---

## 对比总结

| | 训练 | 推理 |
|---|---|---|
| 谁控制终止 | **人**（预设词汇量上限） | **算法**（自然穷尽） |
| 终止条件 | `len(vocab) >= 50000` | 没有可合并的相邻对 |
| 循环次数 | 精确可控（上限 - 256） | 取决于输入文本 |
| 不可终止吗 | 可以一直跑到语料用完 | 一定会停，最坏情况回到字节级 |
